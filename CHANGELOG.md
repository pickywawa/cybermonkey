# Cybermonkey 1.2.0

**Cybermonkey arrive sous Windows** (Windows 10/11, x64) avec un installateur NSIS.

- **Installateur Windows** `Cybermonkey-1.2.0-win-x64.exe` (par utilisateur, dossier modifiable, raccourcis). Non signé : SmartScreen demande « Informations complémentaires → Exécuter quand même ». Construit sur un vrai runner Windows, avec typecheck, 84 tests, test de fumée du paquet (binaires natifs Appium, Claude Code, Codex, Copilot, sharp présents et chargés) et démarrage de l'app vérifié.
- **Android sous Windows** : SDK détecté automatiquement (`%LOCALAPPDATA%\Android\Sdk`, `ANDROID_HOME`), JDK d'Android Studio ou installé (Temurin, Microsoft, Zulu…) détecté, `adb` retrouvé même hors du PATH. Création IA, enregistrement, import, campagnes, imprévus, environnements, MCP, vidéo, journal (logcat) et comparaison visuelle fonctionnent.
- **iOS n'est pas pris en charge sous Windows** : simulateurs, compilation de WebDriverAgent et détection des iPhone exigent macOS et Xcode. Un mode avancé (WDA externe, iOS 18+, tunnel RemoteXPC) reste dans les réglages, ni testé ni garanti.
- Fenêtre : cadre natif Windows (boutons réduire/agrandir/fermer), barre de menus masquée (Alt pour l'afficher). Mises à jour intégrées : ouvrent l'installateur Windows.
- CI sur macOS **et** Windows ; le workflow *Windows installer* attache l'installateur à chaque release publiée.
- Corrigé : le fichier de verrouillage ne contenait que les binaires natifs de macOS (`npm ci` échouait sous Windows) ; les binaires `win32-x64` sont maintenant déclarés.
- Documentation : README, page Aide (installation et Android sous Windows), page Fonctionnalités (tableau des limites macOS / Windows).

# Cybermonkey 1.1.0

Cette version rend les tests plus **tenaces** (imprévus, relances, historique), plus **expressifs** (nouveaux pas, logique, environnements) et plus **faciles à diagnostiquer** (vidéo, journal, comparaison visuelle).

- **Imprévus** : popups, toasts, message « session expirée », écran de connexion inattendu, dialogue de permission, plantage de l'app. Quand un pas échoue, Cybermonkey regarde d'abord si quelque chose s'est mis en travers : app disparue (relancée), dialogue système (permissions accordées, suivi refusé, jamais un bouton qui supprime/déconnecte/paie), **gestionnaires d'imprévus** (scénarios déclenchés par l'écran affiché, enchaînables, avec reprise « rejouer le pas » ou « revenir à l'écran d'origine » par les navigations connues), puis l'IA en dernier recours (ferme une popup sans effet métier). Tout est tracé dans le rapport et dans MCP (`interruptions_handled`) ; réglage *Imprévus* ; en création, dialogues système répondus pour l'agent et rejeu qui applique vos gestionnaires.
- **Environnements** (recette, préprod…) : variables propres à chaque environnement qui remplacent les variables communes, sélecteur global dans la barre latérale (création, exécution, essais, MCP `select_environment`), nom de l'environnement dans chaque rapport.
- **Fiabilité** : *relance ciblée* d'un pas dont le composant est introuvable ou la vérification en échec (2e essai court ; jamais après une saisie, un défilement ou une erreur d'appareil ; réglable) — réussi au 2e essai, il est marqué **instable** au lieu d'être masqué ; *appui perdu* sur une navigation (app encore en train de démarrer) : le tap n'est répété que si l'écran est inactif et que le composant touché est toujours là, et l'app est attendue stable après un relancement (corrige les échecs « Écran destination non confirmé » de `run_navigation` au premier essai) ; *historique de stabilité* par pas (passé 8 fois sur 10, régression, instable) dans Progression et via l'outil MCP `flaky_steps`, repris dans chaque échec (`history`) ; *audit des sélecteurs* (durables / liés au texte / fragiles / par position) : avertissement dans l'éditeur et à la création IA, outil `audit_selectors` avec l'identifiant à demander aux développeurs et comment l'ajouter ; *réparations IA* : bandeau « N sélecteurs réparés, tout appliquer » et outil `apply_healed_selectors`. Un échec « enfants » n'est plus présenté comme un problème d'appareil.
- **Diagnostic** : *vidéo* de chaque scénario, gardée seulement s'il échoue (lecture dans Résultats, positionnée avant le pas ; réglage dédié ; indisponible sur un iPhone réel sans ffmpeg, sans effet sur le résultat) ; *journal de l'appareil* joint au pas échoué (syslog iOS filtré sur le processus de l'app, logcat Android) avec détection de **problèmes réseau** (hors ligne, délai, refus, TLS, 5xx, 401/403), transmis à l'analyse IA et à MCP (`device_log`, `network_hints`) ; *comparaison visuelle* avec la dernière réussite du même pas (zones modifiées entourées, % de l'écran, bouton dans Résultats et `since_last_pass` dans MCP). 
- **Vitesse** : *profil de durée* (Exécution → Progression : pas les plus lents, part du temps passée en preuves ; chaque pas mesure désormais « action » et « preuves » séparément) et outil MCP `slowest_steps`  avec suggestions ; *raccourci par lien profond* : un écran de départ peut porter un lien (par OS) essayé avant de relancer l'app et de rejouer un parcours, avec repli sûr si le lien n'atterrit pas au bon endroit ; la saisie dans une web view attend le clavier au lieu d'un délai fixe de 350 ms.
- **Logique dans les scénarios** : *conditions* (« exécuter seulement si… » : non remplie, le pas et ses enfants sont ignorés sans échec), *appel de sous-scénario* (réutiliser « Se connecter » sans le copier ; un scénario appelé ne peut être supprimé tant qu'il est utilisé, les boucles d'appels sont refusées), *jeux de données* (un scénario joué une fois par ligne, colonnes = variables, app relancée entre deux lignes) et *capture de valeur* (lire un texte à l'écran dans `${NOM}`, avec expression régulière facultative, réutilisable dans les pas suivants). Éditeur, arbre (pastilles), création IA (réparation des propositions) et MCP (`add_nodes`, `update_node`, aperçus) les connaissent ; les rapports indiquent la ligne de données ; un pas joué sur plusieurs lignes compte pour son pire résultat.
- **MCP : 45 outils** (13 en exploration, dont 8 nouveaux) : `long_press`, `double_tap`, `scroll_to`, `check`, `open_link`, `answer_alert`, `app_control`, `rotate`.
- **Pas plus riches** (Android + iOS) : appui long, double appui, *défiler jusqu’à ce qu’un composant soit visible* ; lancer / relancer / fermer / mettre en arrière-plan l’application ; **ouvrir un lien profond** ; répondre à une alerte ou permission système (accepter, refuser, ou libellé du bouton, avec attente) ; orientation ; masquer le clavier. Nouvelles vérifications : sélectionné, expression régulière, nombre de composants (`3`, `>=2`, `<5`). Disponibles dans l’éditeur, dans la création IA et via `update_node` / `add_nodes` du MCP.
- **Serveur MCP intégré** (Réglages → MCP) : activé par défaut, local (127.0.0.1), jeton d’accès, désactivable ; chaque outil activable par groupe. 32 outils : lecture, observation (capture, composants, rapport, chemin), exécution (scénario, campagne, dossier, élément, navigation, annulation), création (création IA, rejeu, insertion, édition), utilitaire et exploration (clic, saisie, retour). Résultats structurés par OS avec explications et pistes de correction. Voir `docs/mcp.md`.

# Cybermonkey 1.0.0

Nouvelle base de code issue de Cyberfox.

- Architecture en couches (domaine partagé, processus principal, interface), contrat IPC unique et typé.
- Fournisseur **Claude Code** ajouté (Agent SDK) aux côtés de Codex et GitHub Copilot.
- Création par IA plus résiliente : réponses tolérantes, relances, réparation déterministe des propositions, brouillon depuis la trace, synthèse avec sélection étape par étape.
- Exécution : réparation de sélecteurs par IA (actions/navigations), analyse structurée des échecs, sélecteurs de secours, glisser/attendre.
- Cartographie et avancement par OS et par scénario (écrans prévus vs testés).
- Un OS à la fois ou les deux ; étapes propres à un OS ; plateforme Flutter retirée (Android + iOS).
- Création manuelle depuis le miroir, enregistrement sur le téléphone, import Squash TM / TestRail / Azure / Gherkin / CSV / JSON / Markdown.
- Diagnostic d’appareil enrichi (commandes, documentation, diagnostic IA), erreurs expliquées.
- Exports HTML, JUnit XML et JSON en plus de texte, CSV, Markdown et Confluence.
